## 2. Feature Status Consistency & Multi-Dimensional Matrix

### 2.1 Root Cause of Initial Discrepancy
The previous reporting of "3 of 9 features tested" and "7 mocked" stemmed from two substring matching bugs in `scripts/retro.py`:
1. **Testing False Negatives:** The condition `not any(w in tested.lower() for w in ("not yet", "no", "—", "-"))` performed naive substring matches for `"-"` and `"—"`. Any test cell containing a dash (e.g., `scans/blurry → "unreadable — ration_card"`, `2023 income proof → "old — income_proof"`, `flagged, not matched`, `no Aadhaar number stored`) was incorrectly classified as untested.
2. **Mocking False Positives:** The `Mocked` column frequently contains `"n/a"` to indicate that a feature is a real build and has no mocked simulation. Because `"n/a"` did not match `"no"` or `"none"`, it defaulted to `is_mocked = True`, erroneously categorizing real builds (such as checklist loading, validity rules, flag logs, and Aadhaar masking) as mocked.

### 2.2 Independent Status Dimensions
A feature can simultaneously possess overlapping statuses across different facets:
- **Planned:** `Build` vs `Mock` vs `Cut` (from `PLAN.md`).
- **Implementation:** `Built` (code/route exists) vs `❌ Not built` (unbuilt task) vs `Planned mock` (mocked in plan, no production code).
- **Tested:** `✅ Tested [V]` (observed live by Claude) vs `✅ Tested [T]` (reported by team) vs `⚠️ Untested`.
- **Demo Presentation:** `Shown` (full live demonstration) vs `Shown (partly)` (text/partial) vs `Not shown` (manual/omitted).
- **Mock Status:** `⚠ Mocked` (simulation or stub used for demo) vs `Real (unmocked)` (real logic and storage).

## 3. Causal Analysis Rigor & Classification

Causal assertions in `scripts/retro.py` have been reviewed and classified into four deterministic evidence tiers:

1. **`[Direct Cause]`**
   - *Untested Killer Assumptions:* When open "collapses" assumptions remain unvalidated at trial, `tally.py` enforces a procedural cap restricting the verdict to `REVISE`. This is a direct engine rule.
   - *Demo Day Court Failures:* When jurors vote GUILTY in Demo Day Court due to unbuilt live integrations and pitch disclosure gaps, the causal link between prototype shortcomings and jury rejection is directly cited from juror ballots.
   - *Pitch Drill Penalties:* When pitch claims claim features as "built" that `DEMO.md` documents as mocked or unbuilt, the honesty score drops directly.
2. **`[Contributing Factor]`**
   - *Planning Overload vs Unbuilt Tasks:* When a team member assigned >80% capacity owns a feature that remains unbuilt at freeze (e.g., Folder Watcher owned by Member A), workload pressure is documented as a *probable contributing factor*, explicitly noting that task prioritization may also explain the omission. Spurious claims of sole causation are prevented.
3. **`[Correlation]`**
   - *General Utilization:* High critical-path utilization (e.g. 14h of 18h) without a dropped task on that path is classified as an observed operational condition reducing team buffer, not a failure cause.
4. **`[Unknown / Unverified]`**
   - When projects pause prior to late phases (e.g., Phase 10 lock), missing build or trial data is explicitly labeled as `[Unknown / Unverified]`.
