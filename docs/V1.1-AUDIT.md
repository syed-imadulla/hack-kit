## 2. Verified Implementation Status

### A. v1.0.1 Foundation & Backward Compatibility
- **Evidence Label System:** Strictly enforced across templates, commands, and `lint_project.py`. Only `[V]` (verified) and `[T]` (team-reported) validate claims. `[AI]` inferences and `[?]` unknowns cannot validate.
- **Hack Court 2.0:** 12 jurors with distinct personas defined in `skills/hack-court/jurors.json`. Quick mode uses 7 jurors including the sceptic. Six domains (healthcare, agriculture, education, finance, civic, climate) swap in domain experts without duplicating the end-user.
- **Tallying Logic:** `scripts/tally.py` rigorously validates votes, maps harmless synonyms in memory (`moderate` → `medium`), rejects invalid/duplicate replies, calculates decision rule (`PASS`, `REVISE`, `FAIL`, `INCONCLUSIVE`), and caps `PASS` to `REVISE` when `--open-collapses > 0`.
- **Packaging:** `scripts/build_claude_ai.py` dynamically bundles all commands, skills, and templates into `claude-ai/hack-kit/` and `docs/downloads/hack-kit-skill.zip`.
- **Compilation:** `scripts/compile.py` compiles `.hackathon/` into `FINAL.md`, `FINAL.html`, and `FINAL.pdf` (or `BRIEF.*` with `--brief`).

### B. v1.1.0 New Features
- **Event Profiles (`scripts/profile.py` & `profiles.json`):**
  - Evaluates 6 event types (`college`, `sih`, `ai-ml`, `ideathon`, `hardware`, `corporate`), 4 lengths (`12h`, `24h`, `36h`, `48h+`), 3 experience levels (`beginner`, `mixed`, `advanced`), and 4 judging focuses (`balanced`, `technical`, `innovation-impact`, `business`).
  - Supports `--json` and markdown generation (`## Profile`).
  - Every phase command explicitly specifies the profile settings it reads.
  - Phase skips (e.g. ideathon skips plan & demo court) and team size adjustments (small teams <= 2 disable parallel validate/compete) are verified.
- **Team-Aware Planning (`scripts/plan_check.py`):**
  - Parses `## Team` and `## Tasks` tables from `PLAN.md`.
  - Calculates topological sort and critical path duration.
  - Detects dependency loops, unknown dependencies, unassigned tasks, and skill gaps (accounting for multi-owner tasks).
  - Flags member overload (>85% capacity with spare-capacity rebalancing recommendations) and underutilization (<40%).
  - Checks critical path against `Hours until code freeze`. Excludes `maybe` conditional tasks from load calculation.
- **Demo Day Court (`/hack:verify --demo`):**
  - Evaluates actual code/endpoints via the feature ladder (planned → built → tested → shown).
  - Enforces the golden rule: features must be run to be considered tested.
  - Step D3b disclosure check verifies "what we'll say about mocks" against the actual state of the code.
  - Runs trial with jurors instructed to evaluate real demo execution.
- **Pitch Drill (`/hack:pitch --drill`):**
  - Simulates a 3-judge rubric panel asking questions one at a time.
  - Scores responses on clarity, evidence, honesty, and length.
  - Directly cross-references pitch claims against `DEMO.md`'s ladder to detect unbuilt or overstated features.
- **Safe Parallel Development:**
  - Standardizes teammate contributions in `## Pending from <name> — <time>` blocks.
  - `lint_project.py` detects unmerged pending blocks and unresolved `CONFLICT` tags.

## 4. Problems, Edge Cases & Inconsistencies Found

### Critical & Medium Issues
1. **Merge Protocol relies entirely on LLM Interpretation:**
   `/hack:status --merge` has no underlying Python script. If two teammates edit table rows or assumptions, the captain relies on Claude prompt following to resolve diffs. If the LLM makes an error or truncates, data loss or table syntax corruption can occur.
2. **Non-Standard Unit Test Structure:**
   Running `python3 -m unittest discover -s tests` discovers 0 tests because `test_*.py` files use custom `run()` methods instead of `unittest.TestCase`. While `scripts/check.py` runs them via subprocesses, standard automated CI tooling (like GitHub Actions test matrix or IDE runners) cannot discover them natively without `check.py`.
3. **Lack of Graceful CLI Error Handling in Helper Scripts:**
   - `python3 scripts/lint_project.py` without args crashes with `Folder not found: .hackathon`.
   - `python3 scripts/compile.py` without args exits with `Folder not found: .hackathon. Run /hack:start first.`
   - `python3 examples/test-run-certificates/app/onetrip.py` throws uncaught `IndexError` if run without a scan folder argument.
4. **Minor Documentation & Example Sync Gaps:**
   - In `commands/ship.md` Step 4, `DEMO.md` is omitted from the list of joined files in the explanatory text, despite being present in `scripts/compile.py`.
   - In `examples/test-run-certificates/.hackathon/STATE.md`, the Demo Day Court check (`court/demo-1/`) and Pitch Drill runs were not logged in the state table or decisions log, leaving Phase 12 marked only with the earlier pre-build verification.
5. **Cross-Platform / Antigravity Execution Considerations:**
   Commands assume `${CLAUDE_PLUGIN_ROOT}` is set in the environment or falls back to `~/.claude/plugins/cache/*`. In Antigravity IDE, commands need clear fallback paths (such as relative directory lookup or workspace root resolution) so teams running outside Claude Code do not encounter broken script paths.

## 5. Recommended Fixes for v1.1.x

1. **Add Deterministic Merging Script (`scripts/merge.py`):**
   Implement a Python helper to parse `## Pending from <name>` sections, detect table row diffs, append new rows, and cleanly output `CONFLICT` markers when conflicting edits occur on the same row key.
2. **Convert Tests to Standard `unittest.TestCase`:**
   Wrap `test_profile.py`, `test_tally.py`, and `test_plan_check.py` into standard `unittest` test suites while keeping standalone CLI execution intact (`if __name__ == '__main__': unittest.main()`).
3. **Add Argument & Usage Guards to CLI Scripts:**
   Allow `lint_project.py`, `compile.py`, and `onetrip.py` to print `--help` / usage instructions when called without arguments or when `.hackathon` is not found.
4. **Sync Documentation and State Example:**
   Add `DEMO.md` to `commands/ship.md` text and update `test-run-certificates/.hackathon/STATE.md` to record the completed demo trial and drill.

## 6. Proposed v1.2 Roadmap: "Prove It"

With v1.0 ("Think deeper") and v1.1 ("Build smarter") verified, v1.2 should focus on **real-world evidence, idea transformation showcases, and post-hackathon retrospectives**:

### Phase A: Hackathon Retrospective (`/hack:retro`)
- **Command:** Add `/hack:retro` (Phase 15 or post-ship utility).
- **Functionality:** Post-event debrief comparing planned vs. actual outcome:
  - Assumptions that were validated vs. invalidated.
  - What broke in the demo vs. what worked.
  - Specific judge feedback recorded during live judging.
  - Quantified delta: time spent on ideation, number of pivots, accuracy of task estimation.
  - Generates `RETRO.md`.

### Phase B: Real-World Showcase & Transformation Walkthrough
- Document a step-by-step before-and-after evolution:
  - Starting from a weak, generic hackathon idea ("AI app for farmers").
  - Subjecting it to `/hack:decode` and `/hack:stress`.
  - Rebuilding it through `/hack:ideate` and `/hack:improve` into a differentiated, feasible solution.
  - Demonstrating measurable quality metrics (evidence score, clarity rating, reduction in unvalidated assumptions).

### Phase C: Merge & Linter Hardening
- Build `scripts/merge.py` with test fixtures in `tests/fixtures/merge/`.
- Ensure multi-user git flows are mechanically safeguarded against markdown table corruption.

### Phase D: Antigravity IDE & Multi-Agent Optimization
- Provide native Antigravity skill definitions and workflow integration while maintaining 100% backward compatibility with Claude Code plugin specifications.
- Support parallel juror evaluation via native subagent task pipelines where supported.
